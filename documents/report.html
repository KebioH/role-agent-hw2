個人化角色 Agent

人工智慧代理人原理及實務　2026 年 11 月 22 日

從既有角色聊天補上可驗證的細節記憶

本專案讓使用者根據對話樣本、作品台詞或訪談資料建立可編輯角色，並透過持續記憶延續互動。對象可為動漫或電影人物、韓星、歌手、偶像團體中的特定成員，或自創角色；樣本須能辨識來源與說話者，不將團體混成單一人格。

主要使用者是希望與自選角色持續互動的成年使用者，以及製作角色互動展示的開發者。具體問題是：角色雖能聊天，仍可能忘記使用者先前提過的事件，或更正後繼續引用舊資訊。本階段以「記住展示日期、日後查回、日期更正」作為可核對的核心任務。

作業一的延續與範圍調整

作業一提出 OpenClaw、Telegram、角色 Skill 與分層記憶架構。本次提供新增的 Python 工具核心及 OpenClaw 接入器，未搬動日常服務，也未以新的框架取代原有系統。結構化 SQLite 記憶用於保存日期與偏好；原有 EmbeddingGemma 語意索引仍是後續整合項目。

角色資料與互動記憶分開保存

data/persona.json 保存已確認角色名稱、語氣及示例。本次 Aria 是合成角色，示例為「你先說是哪一天」「好 我記一下」，不代表真人或特定作品。角色草稿仍由使用者審核；本包沒有實作從任意原始台詞自動推定人格的完整流程。

記憶資料庫包含 user、role、key、value、source、version、updated。key 例如 presentation；value 保存「週五展示；擔心設備出錯」；source 指向輸入訊息識別碼；version 用於防止舊資料覆寫新更正。此結構不是向量搜尋，也不等於完整長短期記憶系統。

樣本處理與版本發布

normalize 讀取已整理的 JSON 陣列，保留目標說話者的文字，排除 share 類型，依來源、時間、說話者、正文產生雜湊並去重。5 筆測試輸入包含其他說話者、分享與重複訊息，最後輸出 2 筆。LINE TXT、IG 原始 JSON 各版本的完整轉換器尚未完成。

publish 必須帶 --approved，將角色 JSON 保存成雜湊命名的版本檔，再原子替換 CURRENT 指標。load_persona 讀取時核對雜湊，舊版保留供回復。這驗證的是本包角色儲存區，尚未自動同步到原有 yunbot 的 SOUL.md 或 MEMORY.md。

技術選擇

沿用 OpenClaw 作為生成與通道整合基礎；新增 Python 標準函式庫工具，降低相依性。工具循環採行動與觀察方式，最多 4 步；不保存模型內部思考。RAG、主動推播、多 Agent 協作與自我反思不列為此次已完成項目。

工具定義與錯誤處理

呼叫契約

工具入口為 src/role_agent.py。user、role 由可信任呼叫端固定，模型只能填入工具參數；多出的 scope 參數會被拒絕。目前 CLI 預設 demo / aria 是測試範圍，不具有 Telegram 身分驗證功能。

名稱與用途輸入輸出與主要錯誤
memory_put 新增明示事實key、value、source新 record / version=1；同值重試不重複。不同內容撞鍵回 KEY_EXISTS_USE_CORRECT。
memory_get 依鍵查詢keyfound、record；未知為 false / null，不由工具填補內容。
memory_search 找出相關項目query目前範圍內最多 10 筆字面子字串結果；不保證同義詞召回。
memory_correct 更正事實key、value、source、expected_version版本加一並保存舊值；NOT_FOUND 或 VERSION_CONFLICT。
memory_delete 經確認刪除key、confirmed=true移除目前與歷史紀錄；未確認拒絕。未開放給模型選擇。

新增與更正的資料一致性

新增遇到既有但不同內容時，不直接覆寫，要求使用更正工具。更正先查取得到版本，再使用 SQL compare-and-swap 更新；版本不一致時回報衝突。更新與歷史保存位於同一交易中。角色、使用者範圍及 SQL 參數均由程式控制，不將模型輸入拼接進查詢條件。

Agent 端的控制

規劃器只可選擇列出的 4 種記憶操作或 finish。每次決策需為 JSON；未知工具、無效決策、無效參數及格式錯誤均會被攔截。工具最多執行 4 次；沒有結束即返回 STEP_LIMIT，避免持續呼叫消耗資源。工具錯誤作為 Observation 返回規劃器，不自動宣稱成功。

OpenClaw 接入器以 subprocess 參數陣列執行 CLI，不使用 shell=True；逾時、非零退出或缺少文字輸出時回傳可辨識錯誤碼。接入器使用獨立 session，跨輪記憶透過 SQLite 保留。模型是否遵守規則、是否正確選鍵與來源，仍需真實模型測試。

限制：工具白名單限制的是 Python 這一層。OpenClaw Agent 自身的執行權限仍需在隔離的展示設定中控制；提示詞本身不是權限隔離機制。

測試結果與失敗情境

已執行的測試

交付環境為 Linux、Python 3.12；本機與 Windows Podman 容器皆通過 25 項 unittest；容器測試輸出為 Ran 25 tests in 0.033s / OK。原始輸出保存於 evidence/unit-tests.txt；環境資訊保存於 evidence/environment.json。這是工具契約、資料一致性及控制流程驗證，非人格相似度、自然語言理解或真實模型成功率。

測試範圍案例編號檢查內容
記憶生命週期01–05、08–09新增查回、重開連線、修正留歷史、版本衝突、未知與去重
範圍與操作邊界06–07、10–14使用者／角色隔離、拒絕參數注入、搜尋、刪除確認及歷史清除
樣本與角色發布15–18、25說話者篩選、排除分享、去重、資料錯誤、審核與版本完整性

失敗案例一　過期版本更正

狀況：記憶已更新為 version=2，仍以 expected_version=1 更正。結果：工具回傳 VERSION_CONFLICT；現有記憶不被覆寫。原因：使用者或另一執行緒可能已修改內容。解法：重新 get 最新版本，確認仍需更正後再提交。測試 04、24 與 demo 的 stale_update 均涵蓋此情境。

失敗案例二　模型輸出不是有效 JSON

狀況：測試後端回傳 not json。結果：控制器停止，ok=false，trace 記錄 INVALID_MODEL_JSON，不執行記憶寫入。原因：生成模型不一定遵守格式。解法：向使用者回報暫時無法完成；後續可加入一次受限重試或原生結構化輸出。測試 20 與 demo 的 invalid_json 實際重現。

額外失敗測試

持續查詢無法結束時，STEP_LIMIT 終止循環（測試 21）；後端不可用或逾時會回報錯誤（測試 23 的注入故障）；未知工具名稱直接拒絕（測試 22）；角色版本檔遭修改時，雜湊檢查失敗（測試 25）。這些均為受控故障測試，並非聲稱線上服務曾發生相同故障。

尚需進行的實驗

以真實 OpenClaw 模型執行固定自然語言案例，記錄工具選擇正確率、事實召回、未知事件處理、錯誤恢復及延遲；再測 Telegram 端到端與 Podman 重啟。作業三可用相同案例比較改善前後，避免只憑主觀聊天感受下結論。

真正需要保存的驗收證據

保存 Podman／OpenClaw 版本、映像 digest、建置與啟動紀錄、真實模型工具追蹤，以及兩次不同容器對同一資料 volume 的寫入／讀取結果。至少在另一作業系統重跑同組測試，記錄 OS、CPU 架構與差異。Apple Silicon 需另外確認 ARM64 相依套件。

本次沒有把原有 llama.cpp 嵌入服務視為已整合。若期末仍使用它，需一併提供容器、模型取得方式與驗證，不能只依賴開發者主機預先安裝。本次 SQLite 工具不依賴 OpenAI embeddings 額度。
